# 先建状态层，再租世界模型：生成式开放世界游戏调研

**结论先行：** 这个 idea 落在一个真实存在的市场空白里——截至 2026 年 10 月，没有任何公司把"多 agent LLM 导演 + 持久世界状态"和"实时生成的第一视角视频"合在一个可玩产品中——但空白两侧的技术都还没站稳。实时视频世界模型这一侧，最好的公开系统（Google Genie 3）做到 720p/24 fps、约 1 分钟视觉记忆，却只以 60 秒封顶的消费者原型开放、没有 API（[DeepMind](https://deepmind.google/blog/genie-3-a-new-frontier-for-world-models/)；[Google](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/project-genie/)）；开源可用的 Matrix-Game 3.0、HY-WorldPlay、Self-Forcing 系列能在单张 H100 级 GPU 上跑 480p–720p、16–40 fps，但独立基准 WorldRoamBench 的结论是"没有一个模型能稳定满足所有维度，最好的也只拿到中等分数"，30 秒后画质开始崩塌（[WorldRoamBench](https://arxiv.org/abs/2606.31672)）。"做任何事"的叙事一侧，文字游戏（AI Dungeon、Hidden Door）已经证明纯自由会让乐趣短路，幸存者全部转向了结构化约束；长程基准 NCP-Bench 显示即便 GPT-5.2 也只有 42% 的局能撑过 20 回合不出事实冲突（[NCP-Bench](https://arxiv.org/html/2608.08160)）。因此我们的核心判断是：**不要把"世界"存在视频模型里，而要把它存在一个廉价、确定、可验证的结构化状态层里，视频只是渲染器。** 务实路线是先做"3D 一次重建 + 事件视频片段"的混合 MVP（每玩家小时约 $1.5–3，用户照片几秒内变成可自由行走的 Gaussian splat 场景，行为后果用 I2V 片段渲染并经质量门控），再在第二阶段把实时世界模型作为可替换的渲染后端接进来（自托管每玩家小时约 $4–7，走 Decart API 则高达 $72），第三阶段才考虑自训含手部的第一视角模型。你提出的 10 个 agent 角色每一个都能对应到今天可用的开源或 API 组件，但"视频质量控制 agent"应当并入 display 路径做两级门控（<1 秒快速门 + 异步慢判官），且必须有"回退到上一个好帧/改用缓存片段/改为旁白"的降级策略，因为没有任何公开系统演示过在流式世界模型里做在线质量回滚。

## 空白格是真的，但它两侧的地基都还在晃

把 2026 年 10 月的全部样本摆在一张表上，会看到一个干净的分裂：一边是能走但没有故事、规则和记忆的实时视频世界模型（Project Genie、Oasis、Odyssey、Runway GWM Worlds 2、PixVerse R1、Mirage 2），另一边是有故事和部分记忆但只有文字或静态图的 LLM 游戏（AI Dungeon/Voyage、Hidden Door、Character.ai Scenes）。调研没有找到任何一家把两者合流的产品、startup 或学术系统；最接近的是 Runway 把 GWM Worlds 2 定位为含"回合制视觉小说"和"实时游戏"模式，但只开放企业联系表单，以及学术上的 Unbounded（LLM 游戏引擎 + 一致角色图像）和 RPGAgent（叙事/场景/机制三 agent + Unity 渲染）（[Runway](https://runway.com/research/introducing-gwm-worlds-2)；[Unbounded](https://arxiv.org/pdf/2410.18975)；[RPGAgent](https://dl.acm.org/doi/10.1145/3772318.3790326)）。更重要的是资本的流向：2026 年上半年超过 **$30 亿**投入世界模型 startup，但 World Labs（$10 亿，估值约 $50 亿）、Odyssey（$3.1 亿，$14.5 亿）、Decart（$3 亿，约 $40 亿）、General Intuition（$2.2 亿，$62 亿）的宣称客户几乎都是机器人、自动驾驶和影视，General Intuition 甚至明说"世界模型不是产品，是训练场"（[Forbes](https://www.forbes.com/sites/josipamajic/2026/06/30/world-model-startups-raise-3-billion-vcs-bet-beyond-llms/)；[TechCrunch](https://techcrunch.com/2026/06/17/world-model-maker-odyssey-nabs-1-45b-valuation-backed-by-amazon-and-other-big-names/)；[i-scoop](https://www.i-scoop.eu/general-intuition-bets-billions-that-video-games-can-teach-ai-to-act-in-the-real-world/)）。这意味着你的差异化不在预训练，而在"导演 + 持久世界状态"这一层——这一层可以架在租来的世界模型（Odyssey、Decart、Happy Oyster）或开源权重（Matrix-Game、HY-WorldPlay）之上，而且没人在做。

这个 idea 的优势因此很具体：它把三条已经各自成熟的技术线（结构化状态的多 agent GM、单图到 3D/视频的生成、实时视频流式传输）拼成一个新品类，而不是去和 Google、Decart 拼模型；它天然适合"用户上传照片/视频作为场景"这种个性化入口，而 Project Genie 的 Street View 模式和 Mirage 2 的"任意图片变世界"已经验证了这个入口的吸引力（[Engadget](https://www.engadget.com/2176797/project-genie-adds-google-street-view-integration-and-goes-live-for-global-ai-ultra-users/)；[the-decoder](https://the-decoder.com/mirage-2-allows-users-to-turn-sketches-and-photos-into-interactive-game-worlds/)）。

核心风险则有五个，而且彼此耦合。第一是**重访一致性与漂移**：每一个公开的负面评价都指向它——Oasis 被叫做"痴呆版 Minecraft"、WHAMM 只有 0.9 秒上下文"低头再抬头就换了个地方"、Odyssey 预览"转身后布局不一样"、Oasis 3 "回到原地看到的是另一个环境、车穿车"（[Wikipedia Oasis](https://en.wikipedia.org/wiki/Oasis_(Minecraft_clone))；[GameRant](https://gamerant.com/microsoft-quake-2-ai-tech-demo-backlash-poor-performance-dev-impact/)；[TechCrunch](https://techcrunch.com/2026/06/10/decarts-new-world-model-can-simulate-hours-of-photorealistic-driving-with-some-caveats/)）。R2M-Bench 在 2026 年 8 月才把"离开再回来"形式化为独立指标，并指出原始相似度会奖励静止不动的 rollout（[R2M-Bench](https://arxiv.org/abs/2608.27328)）。第二是**每分钟都在烧钱**：Project Genie 的 60 秒上限被 Google 明确归因于算力成本，Death by AI 曾因 OpenAI/ElevenLabs 账单"几乎破产"，Suck Up! 的代币制让"玩家撞墙后乐趣就停了"（[Wikipedia Project Genie](https://en.wikipedia.org/wiki/Project_Genie_(website))；[Lantz](https://franklantz.substack.com/p/why-no-ai-games)；[Mason](https://medium.com/@hmason/the-state-of-ai-native-games-lessons-from-the-frontier-3e696a9e3279)）。第三是**"做任何事"本身不等于好玩**：Lantz 的结论是"一开始就给一堆惊人的复杂性不会带来更多乐趣，只会让整个过程短路"，Hidden Door 的设计原则是"你可以引导、混搭、选择——但不能凭空变出东西"，2026 年一项 Stardew Valley 研究发现接入 LLM NPC 后老玩家的行为投入和共情反而下降（[Lantz](https://franklantz.substack.com/p/why-no-ai-games)；[Arcanum](https://arcanumrpgs.com/blog/hidden-door-review/)；[ACM](https://dl.acm.org/doi/pdf/10.1145/3742413.3789221)）。第四是**物理与规则**：WorldRoamBench 指出开源模型"难以稳定执行碰撞、穿模、地形和光学约束"，GPT-4 预测环境驱动的状态转移只有 44.1% 准确（[WorldRoamBench](https://arxiv.org/abs/2606.31672)；[Wang et al.](https://arxiv.org/html/2406.06485v1)）。第五是**受众敌意与肖像权**：游戏玩家群体对生成式 AI 的态度被形容为"几乎一致的反感"，而针对用户上传照片的 NO FAKES Act 已过参议院司法委员会、2026 年 9 月 30 日院会推进受阻，肖像权仍是州法拼图加你自己的 ToS（[Lantz](https://franklantz.substack.com/p/why-no-ai-games)；[Holland & Knight](https://www.hklaw.com/en/insights/publications/2026/06/senate-judiciary-committee-advances-legislation-to-protect-name)）。

在定路线之前，有几个问题需要你先回答，因为它们会把方案推向完全不同的分支：

| 需要你回答的问题 | 为什么重要 | 对路线的影响 |
|---|---|---|
| 可接受的每玩家小时成本上限是多少？（$0.5 / $3 / $10） | 自托管实时世界模型约 $4–7/小时，混合 3D + 事件片段约 $1.5–3，Decart API 约 $72 | 决定第一阶段能否直接上实时视频 |
| 控制是连续实时（WASD 每帧响应）还是回合/事件驱动（"我要挖地"→看结果）？ | 开源模型首帧延迟 0.45–1.2 秒，只有 Decart/Odyssey 级别做到每帧 <50 ms | 回合制可用片段生成，实时才需要世界模型 |
| 需要画面里出现自己的手/身体吗？ | 所有含手的第一视角模型（PlayerOne、Hand2World、Generated Reality）都没有公开权重 | 要手就必须自训，且需要姿态输入 |
| "做任何事"的边界：哪些规则必须固定（死亡、资源、地形），哪些给语义自由？ | 幸存的文字游戏全部收敛到"有目标、有边界"；无约束被其后继者视为失败设计 | 决定 Interact/Prediction agent 的规则引擎范围 |
| 单人还是多人共享世界？ | 多 agent/多人一致性在 Genie 3 里被列为未解决；只有 PixVerse R1 和学术 MIRA/Solaris 做了多人 demo | 多人会让记忆和缓存设计复杂一个量级 |
| 画面要照片级还是允许风格化？ | 风格化能掩盖漂移（PlayCYOA 用"换地点"掩盖角色漂移），且允许更便宜的模型 | 影响模型选择和 QC 阈值 |
| 场景忠实度：用户照片的那个地方必须"就是那里"，还是"像那里"？ | 单图只能得到正面壳层，背面必须幻觉补全；Genie 3 自己也不保证地理精确 | 决定 3D 重建投入与 QC 中的"场景一致性"权重 |
| 目标平台：浏览器、PC、VR？ | WebRTC 端到端约 80–130 ms；VR 对延迟和手部要求最高 | 影响传输栈与是否需要姿态输入 |

## 同类系统做到了"走一分钟"，失败在记忆、延迟、规则和账单

实时视频一侧，2026 年确实出现了第一批公开可玩的系统，但每一个都是"能导航的视频流 + 短记忆 + 没有游戏规则"。Project Genie 于 2026 年 1 月 29 日向美国 Google AI Ultra（$249.99/月）订户开放，5 月 19 日接入 Street View 并全球开放，画面 720p/24 fps，"探索上限 60 秒"，DeepMind 的解释是"延长上限带来的测试价值相对较小"而算力成本上升；评测称 24 fps "太卡顿"、"没有商业或开发者 API，也没有导出"（[Wikipedia Project Genie](https://en.wikipedia.org/wiki/Project_Genie_(website))；[Cybernews](https://cybernews.com/ai-tools/google-project-genie-review/)）。它在 WorldRoamBench 第一人称总分 73.81 排名第一，Alibaba 的 Happy Oyster（71.06）和 NVIDIA Lyra 2.0（70.32）紧随其后，但论文的结论是"闭源模型在物理和记忆上普遍更好，但没有一个可靠"（[WorldRoamBench](https://arxiv.org/html/2606.31672v1)）。Decart 的 Oasis（2024 年 10 月，500M 参数、MIT 开源）是这条线的原点，Minecraft 风格、20 fps、"一次只能玩五分钟"、没有物体恒存；两年后 Decart 把 Oasis 品牌转向了自动驾驶模拟（Oasis 3，2026 年 6 月，$0.02/秒 API，有漂移和穿模），把消费者产品转向了视频风格化（Lucy 2.5，30 fps、1080p，$0.02/秒），"Oasis 2.0" 只是一个给真实 Minecraft 换皮的 mod——这个轨迹本身就说明"生成的 Minecraft"是一个没有留存路径的营销 demo（[InfoQ](https://www.infoq.com/news/2024/11/decart-etched-oasis/)；[Decart pricing](https://docs.platform.decart.ai/getting-started/pricing)；[CurseForge](https://www.curseforge.com/minecraft/mc-mods/oasis2)）。Odyssey 是唯一公开过单位经济的运营者：2025 年 5 月称 H100 集群上"每用户小时 $1–2"，Odyssey-2（20 fps、每帧 <50 ms、可中途打字改世界）2026 年 1 月开放按申请的 API，CTO 承认当前模型只能"预测 1–2 分钟连贯视频"（[Odyssey](https://odyssey.systems/introducing-interactive-video)；[Odyssey-2](https://odyssey.systems/introducing-odyssey-2)；[Data Exchange](https://thedataexchange.media/jeff-hawke-odyssey/)）。Microsoft 的 WHAMM Quake II demo（640×360、10+ fps、0.9 秒上下文）引来"几乎只是个美化的图像模拟器"的开发者批评，之后团队在 2026 年 9 月并入 Microsoft.AI 产品组，Xbox 2026 年的 AI 路线图是助手 Gaming Copilot 而非生成游戏（[GadgetGuy](https://www.gadgetguy.com.au/game-developers-react-microsoft-quake-ii-muse-generative-ai-preservation/)；[MSR](https://www.microsoft.com/en-us/research/project/wham/news-and-awards/)）。

文字一侧的教训更直接地关乎你的 writer/interact 设计。AI Dungeon 2019 年用 GPT-2 起步、2021 年见顶后衰退，Latitude 后来专门训练 Wayfarer 模型，原因是"玩家一直抱怨现代模型太好人，从不让你失败或死亡"；其 2026 年的 Voyage 加了一个"追踪逻辑的 World Engine"（[Lantz](https://franklantz.substack.com/p/why-no-ai-games)；[HF Wayfarer](https://huggingface.co/LatitudeGames/Wayfarer-12B)；[Latitude](https://latitude.io/news/what-is-voyage)）。Hidden Door（$900 万融资，2025 年 8 月上线授权 IP 世界）把状态做成"卡片"，打字输入不直接执行而是重新生成选项菜单；独立设计评审指出它的世界是"无根的"——物体只在被提到时才获得属性，d20 在 prompt 里但玩家"几乎总是成功"，出现了车→路→车的连续性错误和自动完成的目标（[Ian Bicking](https://ianbicking.org/blog/2025/08/hidden-door-design-review-llm-driven-game)）。Hilary Mason 总结为"受约束的创造力胜出：给玩家可以推的边界，而不是空无一物的虚空"（[Mason](https://medium.com/@hmason/the-state-of-ai-native-games-lessons-from-the-frontier-3e696a9e3279)）。Vaudeville 在 Steam 上评价"褒贬不一"、开发者的 pre-mortem 承认评论"在狂热者和讨厌者之间对半分"（[Game Developer](https://www.gamedeveloper.com/press-release/vaudeville-a-pre-mortem)）。而非 AI 的基线 Netflix 互动剧在 2025 年 5 月彻底下架，游戏负责人 Mike Verdu 的原话是"技术非常受限，潜力被封顶了"（[What's on Netflix](https://www.whats-on-netflix.com/news/netflix-no-longer-making-interactive-shows-and-movies)）。学术侧，Generative Agents（记忆流 + 反思 + 规划）、Voyager（技能库）、Project Sid（1,000 个 agent 在 Minecraft 里形成宗教和货币）提供了记忆与规划原语，但都在符号/引擎渲染的世界里运行，从未与视频生成合流（[ACM](https://dl.acm.org/doi/fullHtml/10.1145/3586183.3606763)；[Tom's Guide](https://tomsguide.com/ai/a-company-gave-1000-ai-agents-access-to-minecraft-and-they-built-a-society)）。

把失败模式合起来看，它们是耦合的：短记忆迫使短会话，短会话恰好也是让成本可忍受的东西；加记忆、加时长就是乘成本。这就是为什么我们建议把"世界"从像素里拿出来，放进一个廉价的持久状态层——这不是品味问题，而是整个行业用真金白银验证过的约束。

## 今天能直接拿来用的技术：渲染层可租、状态层有配方、质量门控有零件

### 实时视频与世界模型：开源在 480p–720p/16–40 fps，闭源 API 每秒 $0.02

几乎所有开源实时模型都是同一个配方：拿 Wan 2.1/2.2（1.3B/5B/14B）或 HunyuanVideo（8B）这样的双向视频 DiT，改成因果注意力 + KV cache，再用 Self-Forcing/Causal Forcing + DMD 做 4 步蒸馏（[Self-Forcing](https://self-forcing.github.io/)；[minWM](https://arxiv.org/abs/2605.30263)）。典型工作点是单张 H100/4090 级 GPU 上 480p、16–25 fps；最高的开源宣称是 Matrix-Game 3.0 的 5B 模型 720p、最高 40 fps，但其项目页注明用了 8 张 GPU 跑 DiT 加 1 张跑 VAE（[Matrix-Game 3.0](https://arxiv.org/abs/2604.08995)；[项目页](https://matrix-game-v3.github.io/)）。下表列出 2026 年 10 月可用的系统；fps 数字来自各厂商自报，分辨率、步数、GPU 型号互不相同，不能直接横比。

### 第一视角 + 手部：全部是论文，没有权重

你描述的"第一视角、我在挖地"在学术上对应一条清晰的"egocentric world simulator"线：PlayerOne（HKU/Alibaba，单张场景图 + 外视角相机捕捉的身体动作）、EgoControl（CVPR 2026，3D 全身姿态条件）、Hand2World（NTU，单图 + 手势，蒸馏成因果生成器）、Generated Reality（Wetzstein 组，头部位姿 + 关节级手部姿态，用户研究显示更高的控制感）、EgoSim（显式更新 3D 场景状态以避免结构漂移）、HandsOnWorld（Plücker Hand Map，在 EgoVid-Pro 上训练）——**没有一个公开了权重**（[PlayerOne](https://arxiv.org/abs/2506.09995)；[Generated Reality](https://arxiv.org/abs/2602.18422)；[EgoSim](https://arxiv.org/abs/2604.01001)；[HandsOnWorld](https://arxiv.org/abs/2607.02075)）。它们还有一个共同点：输入是追踪到的手/身体姿态（VR 头显或外部相机），不是键盘动作，把"挖地"这个离散意图映射成姿态轨迹是额外的工程层。数据方面，EgoVid-5M（500 万条 1080p 第一视角片段 + 动作描述和运动学标注）的 HF 页面返回 401 需申请，Ego4D/Ego-Exo4D 需签许可协议，EPIC-KITCHENS 是 CC BY-NC（[EgoVid-5M](https://arxiv.org/abs/2411.08380)；[Ego-Exo4D](https://arxiv.org/abs/2311.18259v4)）。务实结论是：第一阶段用无手的第一人称游戏世界模型（Matrix-Game、HY-WorldPlay、Yume）或干脆用 3D 场景渲染，手部只在事件片段里由 I2V 模型"演"出来；自训含手模型是第三阶段的事。

### 场景持久性：只有显式 3D 是无界的

四种持久性机制里，相机位姿/FOV 重叠检索历史帧（WorldMem、Context-as-Memory、Matrix-Game 3.0、HY-WorldPlay）便宜且可以叠在任何自回归模型上，但只在分钟尺度验证过，而且被挖的坑、被捡走的东西必须作为更新后的记忆帧重新注入，否则会"复原"；VMem 的 surfel 索引和 GEN3C/Voyager 的 3D 点云缓存把几何渲染回去作为条件；Genie 3 的一致性是"涌现"的、约 1 分钟（[WorldMem](https://arxiv.org/abs/2504.12369)；[Context-as-Memory](https://arxiv.org/abs/2506.03141v1)；[GEN3C](https://github.com/nv-tlabs/GEN3C)）。对于"几分钟后回到挖的那个坑"这种游戏需求，**显式 3D（splat/mesh/点云）是唯一持久性无界的方案**，所以实际设计是混合：3D 世界管静态布局，视频模型管动态事件。单图到 3DGS 已经很快：FlashWorld 在一张 H100 上约 4 秒、A100 约 7 秒生成 splat 场景（Apache-2.0，ICLR 2026 oral），VGGT 单帧 0.04 秒，Depth Anything 3 直接输出 Gaussian，Marble 约 1–5 分钟给出更完整的可探索世界并能导出 SPZ/PLY/GLB（[FlashWorld](https://github.com/imlixinyang/FlashWorld)；[VGGT](https://github.com/N9nGe/VGGT)；[World Labs docs](https://docs.worldlabs.ai/marble/export/gaussian-splat/index.md)）。渲染端 three.js r186 已原生支持 WebGPU splat，World Labs 的 Spark（MIT）覆盖约 98% 设备含手机和 VR（[sparkjs.dev](https://sparkjs.dev/docs/overview/)）。局限也要说清：单张照片只能得到正面壳层，背面必须生成补全，Lyra 2.0/Voyager 能扩大覆盖但每场景要几分钟数据中心 GPU（[i-scoop](https://www.i-scoop.eu/nvidia-lyra-2-0-generates-explorable-3d-worlds-from-a-single-image/)）。

### 多 agent 叙事：赢的分解方式是"结构化真相源 + 只渲染被交付结果的叙述者 + 后台写状态"

学术证据在这里出奇一致。ChatRPG v2 把单次 GPT-4 调用拆成前台 Narrator 和后台 Archivist（JSON 实体状态入库），N=12 的受试内研究在连贯故事（1.00→2.25，p=.040）、沉浸（p=.034）、掌控感（p=.004）等 8–9 个构念上显著更好，拆分的直接动机是"单个 agent 必须先更新完状态再叙述太慢"（[ChatRPG](https://arxiv.org/html/2502.19519v2)）。其 v3（SENNA）加了先于每回合运行的 Examiner（返回 允许/有条件允许/不允许 + 有根据的理由）和 Navigator（校验叙事图边条件），并用专家 GM 和玩家研究比较六种"拒绝玩家"策略：**世界内后果最受欢迎，NPC 劝阻其次，硬拒绝最差**（[AAU thesis](https://projekter.aau.dk/projekter/files/784680954/Narrative_Adherence_in_LLM_driven_Games.pdf)）。Labyrinth GM 显示让 GPT-4 自由改写状态在单元测试上只得 0.267，函数式更新得 0.461；结构化知识树（SKT）侦探游戏把严重幻觉减少 64.78%、彻底消除提前剧透（[Labyrinth](https://arxiv.org/html/2409.06949v1)；[SKT](https://arxiv.org/abs/2609.23043)）。反面的警告来自 NCP-Bench：事实冲突是主要失败（GPT-5.2 40% 到 Qwen3-235B 68%），而加分层工作记忆把承诺冲突从 26% 压到 4% 的同时把"无视/改写玩家输入"从 13% 推到 38%——过度的记忆执行会把游戏变成铁轨（[NCP-Bench](https://arxiv.org/html/2608.08160)）。后果预测上，GPT-4 在文本游戏状态预测中整体 59%、动作驱动 76.1%、环境驱动只有 44.1%，错误集中在算术和常识物理，所以"骰子、库存、锁、伤害"这类有闭式语义的转移必须在代码里算，LLM 只预测开放式常识效果的结构化状态差分（[Wang et al.](https://arxiv.org/html/2406.06485v1)；[Text World Models survey](https://arxiv.org/pdf/2606.09032)）。还要对抗谄媚：ELEPHANT 基准显示 LLM 比人类多 45 个百分点倾向保全用户"面子"，所以成败判定要在叙述之前由代码抽样决定，Writer 只拿到既定结果（[ELEPHANT](https://www.alphaxiv.org/abs/2505.13995.md)）。记忆表示上，Generative Agents 的"新近 × 重要性 × 相关性"检索加周期性反思，消融实验里去掉记忆让可信度从 29.89 跌到 21.21（[Generative Agents](https://arxiv.org/html/2304.03442v2)）。Unbounded 证明蒸馏到 Gemma-2B 的世界模拟 LLM 每场景约 1 秒（7B 约 5 秒），支持"内循环用小模型、创作/反思用大模型"的分层（[Unbounded](https://arxiv.org/html/2410.18975v1)）。给视频模型写 prompt 的部分，MovieAgent/FilmAgent 的共同结构是"剧本→场景→镜头"层级规划加角色库（名字、参考图、声音样本），多 agent + CoT 的人工评分 3.82 高于单 GPT-4o 的 3.55，但"2026 年中没有任何模型能在多个视频片段间做到完美角色一致"（[MovieAgent](https://arxiv.org/html/2503.07314v1)；[Fora Soft](https://www.forasoft.com/learn/ai-for-video-engineering/articles-ai/character-scene-camera-consistency-production)）。投机执行方面，Speculative Actions（ICLR 2026）给出理论上限 50%、实测约 20% 的延迟节省，下一步动作预测准确率最高 55%，加入历史轨迹记忆后可超过 50%（[Speculative Actions](https://www.cs.columbia.edu/~kkaffes/papers/speculative-actions-iclr26.pdf)；[Speculate with Memory](https://arxiv.org/pdf/2607.12236)）。编排框架 LangGraph、Microsoft Agent Framework 为 MIT，Letta 为 Apache-2.0，都支持图工作流、检查点、流式和 MCP（[GitHub](https://github.com/microsoft/agent-framework)）。

### 视频质量控制：没有现成的"能不能给用户看"判官，但零件齐全

首先要纠正一个直觉：VBench-2.0 那些 82–99% 的人类相关性是在**模型级别**（4 个模型排序）上算的，它是跑几小时的基准，不是逐片段门控；FVD 被多篇论文证明偏向逐帧内容、对时序不一致不敏感，不能当 QC 信号（[VBench-2.0](https://arxiv.org/html/2503.21755)；[Ge et VideoReward（Qwen2-VL-2B，代码 MIT）成对准确率 59.69%，是 2025–26 年学术 RL $0.004），不适合打质量分（[Google Cloud pricing](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing)）。亚秒级可用的组件有：DOVER-Mobile（CPU 1.4 秒，9.86M 参数）、AIS 2024 挑战赛的高效 VQA（30 帧约 100 而重生成要 44–51%；LatSearch 用 3B 潜空间奖励模型在第 10–20 步给 N=6 个候选打分，运行时间比 EvoSearch 少 79%，VBench-2.0 比 best-of-4 VideoReward 多约 1 分（[Early Failure Detection](https://arxiv.org/html/2603.14320)；[LatSearch](https://arxiv.org/html/2603.14526)）。连续性检查没有现成验证器，可组合的配方是 ArcFace 看角色脸、SAM 2/3 + DINOv3 跟踪关键物体、SIFT/RANSAC 或 VGGT 看前一片段末帧与下一片段首帧的几何、2–3B VLM Waterloo](https://cs.uwaterloo.ca/~bernard/edgecloud)；[Parsec](https://parsec.app/blog/nvidia-nvenc-outperforms-amd-vce-on-h-264-encoding-latency-in-parsec-co-op-sessions-713b9e1e048a)）。传输默认栈是同卡 NVENC → WebRTC（LiveKit/Pion 自托管或 Cloudflare SFU），720p30 约 5 Mbps 的出口流量每小时只要 $0.09–0.11，传输不到 GPU 成本的 5%（[Cloudflare](https://developers.cloudflare.com/realtime/sfu/platform/pricing/)）。省钱技巧里，RIFE 插帧在中端 GPU 上 1080p 实时，可以让世界模型以 12–15 fps 生成再插到 24–30，代价是约一帧延迟；Real-ESRGAN 到 4K 在 L40S 上只有 2 fps，不实时（[SVP RIFE wiki](https://svp-team.com/wiki/RIFE_AI_interpolation)；[ComfyUI-Upscaler-TensorRT](https://github.com/yuvraj108c/ComfyUI-Upscaler-Tensorrt)）。音频：语音已解决——ElevenLabs Flash 模型延迟约 75 ms、$40/百万字符，Cartesia Sonic 约 80–90 ms，Kokoro-82M Apache-2.0 在 GPU 上首块 45–60 ms，Gemini Live 音频输出 $0.018/分钟；音效用 Stable Audio 3.0 Small（H200 上 0.44 秒，开源权重、年收入 <$100 万免费商用）或 ElevenLabs SFX $0.12/分钟；视频到音频的 MMAudio 权重是 CC-BY-NC 不能商用，HunyuanVideo-Foley 无运行时数据；自适应音乐只有实验性的 Lyria RealTime（WebSocket、无价格、带水印），退而求其次是 Lyria 3.5 每首 $0.08 每约 3 分钟换一次（[ElevenLabs](https://elevenlabs.io/pricing/api)；[The Decoder](https://the-decoder.com/stability-ai-launches-stable-audio-3-0-with-up-to-six-minute-tracks-and-open-weights/)；[Lyria RealTime](https://ai.google.dev/gemini-api/docs/realtime-music-generation)）。内容审核在 0.1 fps 抽样下每玩家小时 $0.36（AWS）到 $1.08（Hive），自托管 Apache-2.0 ViT 分类器边际成本为零（[Sightengine](https://sightengine.com/pricing)；[AWS](https://aws.amazon.com/rekognition/pricing/)）。

## 务实路线：每个 agent 都有现货，MVP 用"3D 一次 + 事件片段"，分三阶段换渲染后端

### 十个 agent 的技术映射

| 你的 agent 角色 | 职责（按证据修正后） | 候选技术（今天可用） | 关键设计约束 |
|---|---|---|---|
| **Interact** | 自由文本/语音 → 类型化意图 {actor, verb, target, instrument, manner} → 对照确定性状态/库存 → 裁决 允许/有条件允许/不允许 + 世界内理由 | 小快模型（蒸馏 2–8B，结构化输出）+ 规则引擎；ChatRPG v3 Examiner 模式；语音入口用 Gemini Live / OpenAI Realtime | 永远返回理由；"有条件允许"路由到骰子/概率解析器而非叙述者；禁止硬拒绝 |
| **Prediction** | 预测行为后果的**结构化状态差分**，不是散文 | 代码即世界模型（骰子、库存、锁、伤害、地形）+ LLM 差分预测（开放式常识）+ 提交前验证；WorldCoder/Text2World 思路 | 成败在叙述前由代码抽样（按分支设种子，方便 Cache 预生成成功/失败两支）；算术/物理属性不交给 LLM |
| **Writer** | 叙述者 + 主线导演：只渲染被交付的结果；按 storylet/承诺推进主线（野兽来袭） | 中/大模型（Claude/GPT/Gemini 级）做叙述；Dramamancer 式 storylet 条件/结果；Wayfarer 式"允许失败"的微调或系统提示 | 主线事件由承诺账本（commitments）触发，不由 Writer 即兴；输出事件到总线供 Memory/Prompt/Film 消费 |
| **Memory** | 三层：结构化 JSON/图（真相源）+ 自然语言情节日志（新近×重要性×相关性检索 + 周期性反思）+ 授权约束层（叙事图/承诺账本） | Postgres/SQLite + 事件溯源；Generative Agents 检索；可选 Letta（Apache-2.0）/Graphiti 做时序 KG；NCP-Bench 式审计器（事实账本 + 承诺 + 玩家输入保真） | "懒生成但一经生成即提交"的世界（Infinite Craft 缓存原则）；后台运行，不阻塞叙述；同时跟踪一致性和玩家意图保真两条轴 |
| **Prompt** | 把叙事节拍翻译成镜头记录 {角色 id→参考图/LoRA，地点 id→参考，固定风格块，景别，运镜，光线，动作，台词，时长} | MovieAgent 镜头 schema + 角色库；Veo 3.1 的 3 张参考图 / Kling 3.0 elements；每次请求附带不可变的风格块和角色表 | 设计节拍让片段前几秒可跨分支复用 |
| **Film** | 把镜头记录变成像素；分阶段换后端 | 阶段 1：Veo 3.1 Lite/Fast（$0.05–0.10/秒，首尾帧+延展）、Kling 2.5 Turbo Pro（$0.07/秒）、Seedance 1.5 Pro、LTX-2（开源）；阶段 2：自托管 Wan 2.2/LTX-2.x（约 $8/小时独特素材）；阶段 3：实时世界模型（Matrix-Game 3.0 / HY-WorldPlay 自托管，或 Odyssey-2 / Happy Oyster API） | 从 Display 当前渲染帧出发做 I2V，尾帧用图像编辑出的"结果关键帧"；延迟几十秒到分钟级，必须靠 Cache 预滚 |
| **Display + 视频质量控制（合并）** | 把 3D 场景、片段、实时流合成并推到浏览器；在送出前做两级门控；执行降级策略 | 渲染：FlashWorld/Marble splat + Spark/three.js（客户端）或 L4 服务端 + NVENC + WebRTC（LiveKit/Cloudflare）；快速门（<1 秒）：DOVER-Mobile 画质、NSFW ViT、ArcFace/DINOv3 连续性、2–3B VLM 是非题；慢判官（异步）：VideoScore2 / VideoReward 重排与审计；去噪第 ~10 步潜空间早退（Early Failure Detection / LatSearch 式） | 合并是对的：门控决策必须和"下一帧放什么"在同一处；降级顺序 = 重采样 → 用缓存片段 → 切镜头/转场掩盖 → 纯旁白；R2M 式重访检查用同 rollout 对照 |
| **Audio** | 旁白/NPC 语音、事件音效、环境音乐 | TTS：Kokoro（Apache-2.0）自托管或 ElevenLabs Flash/Cartesia；SFX：Stable Audio 3.0 Small（0.44 秒）按事件类型预生成缓存；音乐：Lyria 3.5 片段轮换，Lyria RealTime 待其脱离实验状态 | 音效提前约 0.5 秒触发；避免 ElevenLabs Music 连续生成（约 $9/小时）；MMAudio 不可商用 |

### 推荐的 MVP 架构

MVP 应当选 (c)，理由有三：它是唯一一个"回到挖的坑还在"由构造保证的方案；它把最贵、最不稳定的部件（视频生成）限制在事件时刻，这与 Hidden Door、Latitude、PlayCYOA 等幸存者"预结构化并缓存、只在决策点生成"的共同做法一致；它的每玩家小时成本在 $1.5–3，是三个方案里唯一有可能被订阅价覆盖的。具体流程：用户上传照片或视频 → FlashWorld/Marble 几秒到几分钟生成 Gaussian splat（Apache-2.0 或按积分），同时 VGGT/DA3 给出几何与相机 → 浏览器用 Spark 本地渲染，玩家第一视角自由行走，零生成成本、零延迟、完美持久 → 玩家打字或说"我要挖地" → Interact 解析成类型化意图并裁决 → Prediction 在代码里掷骰子/查地形表决定结果、LLM 补充常识差分、验证后提交到 Memory 的 JSON 状态 → Writer 拿既定结果写一段叙述并产出事件 → Prompt 把它翻成镜头记录（当前渲染帧作首帧，图像编辑出的"坑里露出木箱"作尾帧，附固定风格块）→ Film 调 Veo 3.1 Lite/Kling 2.5 Turbo Pro 生成 5–8 秒片段 → Display 的快速门在 <1 秒内检查画质、NSFW、与首帧的 DINOv3/几何一致性、VLM 确认"画面里有坑和箱子" → 通过则无缝切入片段、Audio 同步播放预缓存的挖土音效和 TTS 旁白；不通过则重采样一次，再失败就退回"镜头拉远 + 旁白"→ 片段结束后，结果回写到 3D 场景（最简单的办法是把片段末帧投影成局部贴图或重新 splat 该区域）和 JSON 状态。主线（野兽来袭）由 Memory 的承诺账本按时间/条件触发，经同一条管线渲染。Cache 在玩家行走时就按位置和历史预测 top-2/3 意图提前生成片段，命中则片段延迟归零。整个阶段 1 不需要实时世界模型，GPU 只在事件和（可选）服务端渲染时工作。

### 分阶段路线

**阶段 0（约 4–6 周，纯文字闭环）**：先不碰视频，把 Interact/Prediction/Writer/Memory 四个 agent 跑通，用 NCP-Bench 式的自动审计（事实账本 + 承诺 + 玩家输入保真三类冲突）当内部指标，同时跟踪一致性和玩家意图保真两条轴；目标是在自己的场景上让 50 回合不出严重事实冲突的比例显著高于 NCP-Bench 报告的 42%。这一步的产出是整个产品的"真相源"，之后任何渲染后端都只是插在它上面的消费者（[NCP-Bench](https://arxiv.org/html/2608.08160)）。**阶段 1（约 3 个月，混合 MVP）**：接入上面的 (c) 架构，重点打磨两件事——事件片段的连续性门控阈值（没有论文给出 DINO 余弦的通用阈值，必须用人工标注在自己的风格上校准）和降级策略的无缝程度（用"换镜头/换地点"掩盖漂移是已验证的廉价技巧）。**阶段 2（6–12 个月，实时渲染后端）**：在特定段落（追逐、战斗）把 Display 的 3D 渲染替换为实时世界模型流：自托管 Matrix-Game 3.0 或 HY-WorldPlay（视许可）用 Self-Forcing/minWM 配方在自己的场景风格上微调，或租 Odyssey-2/Happy Oyster API；关键工程是把 JSON 状态和 3D 位姿作为记忆帧注入模型（Matrix-Game 3.0/Context-as-Memory 的 FOV 检索可以叠在任何 AR 模型上），并实现"chunk 级潜空间打分→丢 KV→从上一个好 chunk 重采样"的在线回滚，这是文献里的空白，也是你们的技术壁垒；用 WorldRoamBench 的分段漂移指标和 R2M 的重访增益作为触发器。预算要按 $4–7/玩家小时规划，并用 RIFE 插帧、12–15 fps 生成、spot GPU 把它压向 $2–4。**阶段 3（12 个月以上）**：只有在阶段 2 验证了留存的前提下，才考虑在 EgoVid-5M/Ego-Exo4D（需申请许可）上按 Hand2World/Generated Reality 配方自训含手部的第一视角模型，并评估是否需要姿态输入设备。

必须坦白的未解决问题：重访一致性在视频模型里只在分钟尺度验证过，超过几分钟的物体恒存没有任何跨模型基准；漂移的根因（自回归把自己的输出喂回上下文）在 Odyssey、Decart、Runway 的自述里都没有被解决，只能靠记忆增强和回滚缓解；物理（碰撞、穿模、重力）在 WorldRoamBench/WBench 上没有模型及格；成本上 Decart 的 $72/小时与 Odyssey 的 $1–2/小时之间是 40 倍的差距，说明单位经济高度依赖自己优化服务栈；多人共享世界被 Genie 3 列为未解决；视频 QC 在流式模型里的在线回滚无人演示；音乐的实时自适应只有一个实验性 API。

## 结论

这项调研改变了对问题的认识：决定这个产品成败的不是"哪个视频模型最好"，而是"世界存在哪里"。所有失败案例——Oasis 的痴呆、WHAMM 的 0.9 秒记忆、Hidden Door 的无根物体、NCP-Bench 里 5 回合内崩掉的叙述者——本质上都是把世界存在了一个会遗忘或会幻觉的地方。把世界存进一个廉价、确定、可审计的结构化状态层，让 3D 场景管静态、让视频模型只演事件、让每一次生成都先过门控再给人看，这套设计不仅是今天唯一能把每玩家小时压到几美元的方案，也恰好是行业里没人在做的那一层。你的十个 agent 之所以能一一对应到现货技术，正是因为它们描述的是这一层的分工，而不是模型本身。

往前看，渲染后端会越来越便宜、越来越持久——Matrix-Game 3.5 的 patch memory、RTFM 的位姿帧 KV、HY-World 2.0 的 3D 资产输出都在朝"视频生成器 + 显式空间记忆"的混合方向收敛——这意味着一个以状态层为核心、把渲染器做成可替换插件的架构，会随时间自动受益于模型进步，而一个把世界押在某个特定视频模型记忆里的架构则会随每次模型更新而重写。先在阶段 0 用文字闭环证明"做任何事但有后果"确实比"做任何事"好玩，再决定花多少钱买像素。
